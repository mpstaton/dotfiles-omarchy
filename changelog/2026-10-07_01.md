## Why Care?

On a 2560×1600 laptop panel, Hyprland runs at scale 2, so every app draws at 200%. Web pages
are easy to fix with Ctrl +/−, but Zen's sidebar, tab list and URL bar had no such control, and
they ate a large slice of a 1280×800 effective screen. Now they're 80% of that size, and the
setting lives in this repo like every other config.

## What's New?

- **New `zen` Stow package.** `user.js` in Zen's profile sets `layout.css.devPixelsPerPx` to
  `1.6` (80% of Hyprland's 2.0).
- **Git identity moved out of the public repo.** `[user]` now lives in a gitignored
  `user.local` that the git config includes.
- **Riders:** direnv hook in `.bashrc` plus a `direnvrc` that loads nix-direnv, `pnpm` in mise,
  and a global git ignore for `.claude/settings.local.json`.

## How It Works

The earlier Garuda setup scaled apps per launcher, editing each `.desktop` file's `Exec=` line
with `--force-device-scale-factor`. That works for Chromium and Electron apps like Vivaldi,
Obsidian and VS Code. Zen is built on Firefox, which ignores that flag. On Wayland,
`GDK_SCALE` only takes whole numbers, and Omarchy already sets it to 2. Firefox's equivalent
is `layout.css.devPixelsPerPx`: `-1` follows the compositor, and any positive number
replaces it. The downside is that web pages shrink with the UI. A default zoom of 125%
brings them back to their old size.

## The Gotcha

Zen reads `user.js` only when it starts, and it stays running as long as any window is open.
Two restarts "didn't work" because the browser process from the day before (two windows, on
workspaces 3 and 4) never exited. To check:

```bash
ps -o lstart= -p "$(pgrep zen-bin | head -1)"
```

A `kill -TERM` quits Zen the normal way and saves the session, and relaunching it applied the
setting.

## Under the Hood

- The package folder is named after this machine's random Zen profile ID. On another machine,
  rename it to match `Default=` in `~/.config/zen/installs.ini` before running `stow`.
- `~/.config/git` is one Stow link to the whole folder, so `user.local` sits next to the config
  in the repo and `.gitignore` keeps it out of commits.
